# a2.8 interactive media

Faber displays supplied chart, geographic and diagram data and runs small saved
HTML/JavaScript demos. All use `media_show`, immutable chat attachments, the
native Save As chooser and the existing encrypted remote media transport.
There is no new service dependency, remote CDN or media decoder dependency.

## Supported descriptions

A chart is JSON saved as `.chart.json`. `type` is `bar`, `line` or `scatter`.
Each series has a name and points with `x`, `y` and an optional label. Bar
categories are strings or finite numbers; line/scatter X coordinates and all Y
values are finite numbers. Optional `title`, `xLabel` and `yLabel` label the view.

```json
{"type":"bar","title":"Reviewed output","series":[{"name":"Units","points":[{"x":"Q1","y":4},{"x":"Q2","y":9}]}]}
```

A map is a `.geojson` FeatureCollection. Point, MultiPoint, LineString,
MultiLineString, Polygon, MultiPolygon and bounded GeometryCollection are
supported. Properties are scalar data, with no executable styles or network
configuration. Coordinates use longitude/latitude. The viewer uses an
equirectangular projection and a geographic grid, without external tiles.

A diagram is `.diagram.json` with `nodes:[{id,label,shape?,x?,y?}]` and
`edges:[{from,to,label?}]`. Shapes are `rect`, `ellipse` or `diamond`. Supply
coordinates for every node or omit them for automatic directed layout; cycles
use a stable grid. Labels are inert text. Long node labels wrap and remain
available in full in the inspector. Edges point to shape boundaries.

All three viewers support selection, hover inspection, keyboard selection,
drag pan, zoom and source saving. Chart legend buttons toggle series.
Unknown configuration fields, nonfinite numbers, invalid identifiers,
unclosed polygon rings and excessive nesting are rejected.

| Format | Source limit | Content limit |
| --- | --- | --- |
| Chart | 2 MiB | 12 series, 5,000 points total |
| GeoJSON | 4 MiB | 1,000 features, 20,000 positions, nesting depth 3 |
| Diagram | 1 MiB | 200 nodes, 600 edges |
| HTML | 2 MiB | 32 declared assets, 16 MiB including root |
| HTML asset | 8 MiB | JS/MJS, CSS, JSON, BIN, PNG/JPEG/WebP/SVG, WOFF/WOFF2/TTF/OTF |

## Saved HTML and assets

Publish a demo with `media_show {path:"demo.html",assets:[{path:"demo.js"},
{path:"demo.css"},{path:"pixel.png"}]}`. A safe relative `name` can give an asset
a virtual path such as `assets/demo.js`. Every path is independently authorized
and copied. Duplicate names/IDs, dot segments, URLs, reserved entry names and
unsupported assets are rejected. The manifest is bound to the root and each
child's SHA-256 revision, MIME type and size. Assets are reachable only through
that manifest; an HTML URL cannot select a host path.

The preview starts only with the user's Run action. The desktop creates a
WebContentsView in a private in-memory session at a random `faber-artifact`
origin. A trusted static wrapper contains an opaque `sandbox="allow-scripts"`
iframe. Neither frame has a preload, Node integration or Faber bridge. The
untrusted frame cannot access the parent DOM, the app renderer or its credentials.
The private session is cleared after Stop; every new Run has a fresh origin.

The protocol serves only GET/HEAD requests for the root and declared members.
Each metadata/chunk read rechecks the current chat/device authority, descriptor
and transfer bounds. Responses carry CSP sandboxing, a connection allowlist,
denied permissions, no caching and no MIME sniffing. Host handlers additionally
deny external requests, navigation, popups, downloads, devices and file choosers.
Nested frames, forms, workers, object embeds, external fonts/resources and media
playback are disabled. Generated previews are muted, and WebGL is disabled.

Pause uses the Chromium debugger and animation controls on the isolated frame,
so timers and script execution stop. Resume continues the same demo. Stop
destroys the native view and aborts pending asset requests, even if its JavaScript
is in an infinite loop. Hiding/minimizing the window or covering the viewport
pauses it; switching chat, closing the window, UI reload or paired disconnection
stops it. JavaScript errors appear in the trusted controls. A blocked document
navigation stops the preview instead of leaving an error document running.

A running preview pauses automatically after 60 seconds. A 500 ms process
memory watchdog stops it above 256 MiB. These are availability safeguards,
not a hard OS memory/CPU quota or a guarantee against every browser engine bug.
The existing app/addon and Windows-account authority boundaries still apply.

The implementation uses the bundled Chromium's
[Connection-Allowlist](https://developer.chrome.com/blog/connection-allowlist-announcement)
and Electron's [navigation controls](https://www.electronjs.org/docs/latest/api/web-contents#navigation-events),
[session permission handlers](https://www.electronjs.org/docs/latest/api/session#sessetpermissioncheckhandlerhandler)
and [frame process IDs](https://www.electronjs.org/docs/latest/api/web-frame-main#frameosprocessid-readonly).
HTML is gated to Chromium 152 or later. The tested bundle is Electron 45.2.1,
Chromium 156.0.8078.75.

## Verification

The Windows native fixture uses synthetic files and a disposable profile, with
zero model/provider calls. It exercises the real preload, protocol, normal chat
controls, asset inspector and native view. The same content is then opened through
actual pairing and pinned TLS inside a loopback WebSocket relay.

Observed checks include chart/map/diagram content, label selection, pan/zoom,
chart series selection and unchanged source saves; real HTML JS/CSS/image loads;
separate opaque process without Node/bridge/parent DOM; timers frozen and resumed
with the UI controls; surfaced demo script errors; HTTP/WebSocket/file/app fetch
denials; rejected unlisted assets, popups, frames, forms, navigation, clipboard
and camera; empty file input with native chooser interception; zero requests at
TCP and STUN sentinels; and destruction of an infinite loop within the fixture's
2.5 second bound. Another Run has a different origin and reset state.

The encrypted run also cancels a pending script transfer, restarts the real relay,
requires explicit Run after reconnect and verifies fresh-origin recovery. Revoking
the device tears down its active view and denies further root/asset access.
Every source and child saves byte-identically through the native Save As flow;
the test intercepts the chooser, and cancellation makes no destination write.

Run the standalone source fixture with:

```powershell
npm ci --prefix relay
npm start -- --smoke-interactive-media
```

The installer smoke has a version-gated local interactive probe from a2.8 onward.
It exercises the packaged assets, CSP/native frame, controls, saved originals and
retained root/child attachments on upgrade or rollback. Earlier versions keep
their existing probes. Run it only against an isolated temporary smoke profile:

```powershell
& $faberExecutable --smoke-installed --smoke-profile $temporaryProfile
```

Source tests cover parser/content bounds, immutable graphs, independent owners,
restart retention, rollback-safe suffixes, exact protocol routes, canceled leases,
stream metadata changes and revoked access. Machine-local screenshots and reports
belong in ignored verification storage. Installed-candidate acceptance is recorded
with release verification; physical two-PC/WAN acceptance remains pending.
