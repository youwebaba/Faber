## Trial and limits

`node test/start-schedule-trial.mjs` is the explicit opt-in trial launcher. It
copies public application source into a dedicated temporary cache, hashes the
snapshot, uses the supplied existing CPU model and creates an isolated profile
with sign-in disabled. It first passes the real scheduled report check, then
leaves the Windows worker running with no open windows. `schedule-trial.json`
records actual UTC start, expected daily occurrences, source digest, observed
reports, minute health records, queue pauses/resumes and Windows suspend,
resume, lock and unlock events. The snapshot manifest and host log are retained
beside that private profile. Later development does not change its loaded code.

Seven elapsed days remain a real-time gate. A short test or simulated clock
does not satisfy it. A first report with its deliberate unreadable fixture is
expected to appear for review; a successful summary does not fabricate a
receipt for that input. Audit the daily files, source identities, health gaps,
interventions and unknown usage before marking the trial complete. The launcher
does not declare the seven-day gate complete automatically.
