# Paired work supervision and a stable relay

The home PC continues to own each job, its credentials, the model and the job journal. Open a paired computer’s workspace and choose **Host Work Inbox** to inspect jobs and output receipts, approve a named step, steer an active attempt or stop it. Disconnecting the controller leaves the host working. A changed attempt requires a fresh selection.

For a stable relay on Windows, configure an operator-controlled TLS reverse proxy or named tunnel that forwards its public WebSocket hostname to the relay’s loopback port. Run the relay kit with your hostname:

```powershell
.\Start-FaberRelay.ps1 -PublicUrl wss://relay.example.org -Port 39372 -StartAtSignIn
```

The address, port and route allowlist persist across restarts. `-StartAtSignIn` registers a limited Windows task for the current user with automatic restart on failure. Use `-Stop` to stop the relay, or `-DisableStartup` to stop it and remove that login task. The relay kit continues to support temporary tunnel setup.

When moving an existing pair, save the new relay URL under Connections, then choose **Use configured relay** for that host. Faber verifies the pinned host certificate and existing device credential before recording the new address.

Two isolated Faber profiles used a real relay. Its process restarted on the same port while the controller was disconnected. After reconnecting, the controller found the same approval ID, submitted its approval twice with one resulting effect, inspected the receipt, steered and stopped the job. A separate Windows test registered the optional sign-in task, started and stopped the relay twice in an isolated operator folder, retained its address and allowlist, and removed the test task. Physical two-PC/WAN coverage remains pending.
