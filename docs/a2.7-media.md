# a2.7 supplied music and timed text

MUSIC04, MUSIC05, CAPTION01, CAPTION02 and MEDIA09 extend the existing
`media_show` flow. The UI plays MIDI, groups supplied PCM WAV stems and associates
SRT/VTT captions with audio, video, MIDI or stems. [MEDIA.md](../MEDIA.md) gives
the tool arguments and controls. This release does not generate stems,
separate sources, recognize speech or select a paid provider.

## Playback and ownership

MIDI runs in the existing sandboxed preview origin without Node, a Faber bridge,
parent DOM access, arbitrary paths or external networking. Standard MIDI formats
0 and 1 with metrical timing are supported; SMPTE timing, format 2 and embedded
sound banks are outside this entry point. No external MIDI device is requested.
Play loads the pinned bank; Cancel destroys the preview/worklet/audio context.
Reopen and reconnect start paused.

Stem buffers use the same Web Audio context, scheduled start timestamp and seek
offset. Per-track gains implement mute, solo and volume. Only uncompressed PCM
or float WAV is admitted to grouped playback: header/size/channel/rate checks
bound decoded memory before the browser decoder is called. Individual audio
continues to support the earlier native formats.

Every supplied file is separately authorized and copied into private chat
storage. Group descriptors contain opaque child references and SHA-256 content
revisions. Remote projection keeps one grouped output; ownership lookup can
resolve only its published members. Neither paths nor bytes enter model input.
The `.music.bin` suffix is ignored by the a2.6 pruner, preserving these copies
through rollback. Current deletion removes the owning copies normally.

Subtitles render as inert text, including markup-looking input. Native video
TextTracks provide fullscreen captions; audio/MIDI/stems use synchronized text.
The transcript highlights supplied timing and seeks on click, with bounded
200-segment pages and optional following of the current segment. Turning
captions off leaves transcript navigation and original saves available.

All remote media/image/annotation operations share one cancellable request slot
per paired device, leaving room for chat polling and user commands within the
transport's four-request budget. Canceling a queued operation settles without
waiting for another chat's transfer. Canceling a live transfer reaches the
authenticated host request. Disconnection destroys live music playback state;
reconnect retains member references and starts paused.

## Assets and limits

The pinned upstream packages are `spessasynth_lib` 4.4.7,
`spessasynth_core` 4.4.9, `stb-vorbis` 0.0.7 (Apache-2.0) and `fflate` 0.8.3
(MIT). Synthesizer behavior is unmodified: preparation rewrites only local
module imports and removes source-map references. The fixed module allowlist
and CSP permit the bundled WebAssembly decoder without permitting JavaScript
eval or external code. See the [official library](https://github.com/spessasus/spessasynth_lib)
and [integration guide](https://spessasus.github.io/spessasynth_lib/getting-started/).

The unmodified **FluidR3Mono GM 2.312** bank comes from the
[MuseScore v2.3.2 source distribution](https://github.com/musescore/MuseScore/tree/v2.3.2/share/sound),
which supplies explicit MIT redistribution terms and sample credits.
Its 14,563,174-byte SF3 has SHA-256
`cfcd66d89e8386823400eca64934b14fbea7bf48ba1f00d21189af1262794ec2`.
Required notices are retained under `renderer/vendor/spessasynth`. The bank is
prepared in `.runtime/media-runtime` and packaged as a `media-runtime` resource;
the application downloads no music code or sound bank during playback.

`npm run prepare:timed-media` verifies pinned package SHA-512 hashes and the
bank SHA-256. The generated manifest and package verifier check ten bundled
JavaScript/license files. Existing PDF assets remain independently checked.

| Input/resource | Bound |
| --- | --- |
| MIDI | 4 MiB, 128 tracks, 100,000 events, formats 0/1 with end markers, four-hour duration |
| MIDI synthesizer | 128 voices, 128 MiB decoded sample cache; 15-second sequence-load deadline |
| Grouped stems | 2–8 PCM/float WAV files; 32 MiB per file, 64 MiB aggregate; eight channels per file, 8–192 kHz input |
| Decoded stems | 32 million float samples / 128 MiB at the shared 48 kHz context; header checks precede decoding |
| Timed text | 1–4 SRT/VTT tracks, 1 MiB each; 10,000 ordered nonempty cues, 8,000 characters per cue, end time at most 24 hours |
| Remote media | Authenticated chunks up to 256 KiB, one media operation in flight per device |

## Verification

Source regressions cover parsing limits, inert timed text, grouped ownership,
immutable bytes, current and earlier-version pruning, restart retention,
asset integrity, exact protocol paths and per-device queue cancellation. The
real Electron fixture uses the normal renderer/bridge/store and an encrypted
relay on loopback, with no provider calls. It verifies bank-backed MIDI PCM,
play/pause/seek/volume and cancellation, common-clock stem start/seek offsets,
actual stem PCM, mute/solo/gain controls, caption selection/off, transcript
highlight/click-to-seek, native fullscreen cues and byte-identical originals.

The fixture also holds a real encrypted stem read pending, cancels it from the
UI and observes host cancellation. It stops/recreates the relay adapter,
reconnects previews, retains document notes and verifies paused music state and
revocation. Every restart/disposal phase has a deadline so a stalled check fails
visibly. Native Save As and clipboard writers are intercepted in disposable
profiles; user files and the active profile are untouched.

The installed smoke includes the same bounded local timed-media probe for a2.7
and later. It verifies packaged bank/decoder routing and retains first-run
member references for upgrade/rollback checks; earlier installed smoke remains
compatible.

Physical two-PC/WAN testing is pending. Maximum-size stress, arbitrary MIDI
corpus coverage and fidelity to every hardware synthesizer are not established
by these synthetic test songs. The sound bank and bounded compatibility are
identified rather than implying support for every MIDI variant.
