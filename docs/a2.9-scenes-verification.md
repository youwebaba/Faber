# 3D chat attachments

`media_show` displays static GLB, glTF 2.0 and STL models in chat. For an external
glTF buffer or texture, supply every file explicitly:

```json
{"path":"triangle.gltf","assets":[{"name":"geometry/mesh.bin","path":"geometry/mesh.bin"},{"name":"maps/pixel.png","path":"maps/pixel.png"}]}
```

`path` is relative to the selected project. `name` is the model's safe relative
dependency URI. Each file requires its own normal project read authorization;
the viewer never discovers or downloads dependencies. Missing, extra, duplicate,
traversing or unsupported dependencies fail publication. PNG and JPEG textures
and BIN buffers are supported. External URLs, unreviewed extensions, skinning
and animation are rejected.

The result is one scene reference with immutable `assets:[{name,media}]` children.
Every original has a SHA-256 `revision`; `graphRevision` binds the root revision
to sorted dependency names, revisions, MIME types and lengths. The renderer
checks the graph and every file hash before opening the viewer. Native Save As
also checks revisioned bytes before atomically replacing a destination.

Scenes use `.scene.bin` storage so older releases leave their snapshots alone.
Current pruning retains children while their chat root exists and removes failed
or deleted outputs. Remote controllers request `sceneMode:'references'` only
when the host advertises `sceneReferences`. Existing audio, video, stems,
captions and document references retain their existing shape.

The viewer runs in a separate `faber-preview` origin without the app bridge,
Node or parent DOM access. Its CSP permits only its pinned script/style and
owned resource blobs. Three.js 0.187.0 is bundled with its MIT license;
`scripts/prepare-scenes.mjs` and `build/scene-assets.json` pin the source, bundle,
HTML, stylesheet and license. The loader rewrites only validated buffers and
textures to owned blobs. Stop, offline, chat removal and view disposal abort
transfers and destroy the WebGL context, geometry, textures and blob URLs.

Admission caps include 64 MiB per root/file, 96 MiB per graph, 32 external
assets, 4 MiB JSON, 1.5 million rendered vertices, 8 million pixels per texture
and 32 million texture pixels in total. Accessor bounds, unsigned indices,
finite binary float coordinates, scene trees and decoded work are checked
before rendering. These are static preview limits rather than full glTF support.

## Verification

On 2026-11-09, the full source suite passed with 763 tests passing, no failures
and one unrelated optional native-input fixture skipped. Standard Electron
renderer/bridge smoke also passed. `test/core-scenes.test.mjs` and
`test/core-scene-media.test.mjs` cover all three formats, dependency validation,
graph tampering, original edits, cross-chat denial, failed-publication cleanup,
old-controller projection and rollback-safe storage. The native-media suite
checks that a changed revision cannot replace an existing saved file.

`npm run smoke:media` exercised the production preload, custom protocols, CSP,
media tool and renderer in a disposable Windows profile. Synthetic triangle
models rendered in actual isolated WebGL contexts locally and through the
paired TLS transport over the real loopback WebSocket relay. Chromium input
dispatch exercised pointer-driven OrbitControls in each isolated frame; the
orbit/pan/zoom buttons also changed the camera. Reset restored its initial position. Every
root, BIN buffer and PNG texture saved byte-for-byte through normal media Save
As. Stop during a held encrypted dependency read aborted the actual host
request before a viewer opened. Explicit Stop and an offline transition disposed the viewer. Revocation
blocked a later dependency save. Existing MIDI, synchronized stems, captions,
PDF/DOCX, SVG, GIF/APNG, audio/video and clipboard isolation checks also passed.

The fixture intercepts the native Save As chooser and clipboard writers. It
does not exercise a human operating the chooser, two physical PCs, WAN latency,
arbitrary large real-world meshes, every GPU/driver, or unsupported glTF
extensions. No model/provider request is needed to verify these supplied files.
Release integration must rerun the pinned asset and package checks after merge.
