# Faber a3.0

This is a closed development release for authorized testers.

## Live video

- Share a selected camera, Windows screen or application window locally or with
  one paired PC. Review the source and viewer before the native confirmation and
  Start sharing action.
- A visible Live indicator and Stop control remain available in chat. Hiding or
  closing Faber, reloading, locking Windows, suspending or losing the viewer ends
  the share. Reconnection requires a new host approval.
- Paired viewing sends bounded JPEG frames over the authenticated encrypted
  connection, up to 1280 × 720 and five frames per second. It has no audio and
  records no media to disk. Only the current frame remains in memory.

## Integrated work and media

- Retains reviewed schedules, Host Work Inbox supervision, project permissions,
  independent action receipts, backup/restore and recovery from a2.9.
- Includes PDF/DOCX, SVG, GIF/APNG, MIDI, supplied stems, captions/transcripts,
  charts, geographic data, diagrams, isolated HTML and static GLB/glTF/STL views.
  Saved sources and declared dependencies retain their immutable revisions.
- Scene and HTML dependencies use separate validated storage families. The HTML
  sandbox cannot gain live-capture permissions or Faber APIs.
- Refreshing an unchanged host directory updates the live-view and Work Inbox
  controls when its advertised capabilities change.
- Local model prefill can wait for the run deadline or Stop instead of an
  unrelated 30-second header timeout. The original weights stay unchanged.

## Verification and pending work

Ordinary desktop, encrypted media, live-capture permissions and recovery checks
use isolated profiles and owned fixtures. The live UI fixture selects only a
window created by the test and intercepts its native confirmation; it verifies
real changing pixels through paired encrypted viewing. It does not establish
physical-camera, whole-display or independent-WAN acceptance.

Native Safetensors runs on the verified CPU runtime in this release. The pinned
upstream Mistral.rs Windows CUDA build references paged-attention APIs that it
exposes only on Unix, so that candidate could not build. No engine fork was used.
GGUF llama.cpp and the separate Ollama GPU route were verified independently.
Existing GPU/speculation limits still apply. The installer is unsigned. Physical devices and WAN,
pre-login reboot, controlled live mailbox/calendar trials, the full hardware
matrix and seven actual days of unattended work remain pending during closed
use. They are not implied by source or short fixture passes.
