## Audit the running trial without changing it

```powershell
node scripts/audit-worker-trial.mjs --trial-root '<absolute isolated trial directory>' --expected-source '<independently recorded source SHA-256>'
```

The auditor reads the selected profile, original snapshot manifest and bounded
source/output files. It does not contact worker IPC, open a UI, mutate the
profile, grant permission, start a task or change a process. It checks real
paths, file identity and size while reading. It compares source files against
the manifest and the manifest against a digest independently recorded at start.
Only a whitelist of IDs, hashes, counts, statuses and times is exported; input
contents, prompts, credentials and project paths are omitted.

Expected occurrences are reconciled with admission receipts, stable job IDs,
ten-input coverage, explicit exceptions and actual output SHA-256 values.
Duplicate admissions/effects, missing output, stale health, heartbeat gaps,
source drift and runtime-expired active jobs stay visible. Future occurrences
stay `not_due`. The auditor ignores the old fixture's `observedReports` and
`completedSevenDays` counters when deriving the result. Even seven complete
days return `eligible_for_review`, never automatic release acceptance.

The existing trial digest is
`469542f480ed1596d745d3f92704744ebf65a0174d1a8a370b98f63fcff3d187`.
Its earliest seven-day audit is **2026-11-16 17:20:53.973 UTC**.
At **2026-11-09 19:11:24.911 UTC**, the read-only audit found:

- 111 health samples, no unexplained gaps, no recorded interventions and a live PID.
- One due occurrence, one verified report and one duplicate manual request that reused it.
- Ten inputs: nine hashed summaries and one explicit unreadable-input exception.
- Report SHA-256 `8aa90fb39c1ac746b0fcf58e80225a22c8fbff08457299076394a8c31344316b`.
- Nine recorded local calls, 1,757 known tokens, zero provider spend and no unknown usage.
- Only 6,625,489 ms of observed time. The seven-day gate remained open.

The two attention jobs are expected: the original report and its reused request
both retain the deliberate invalid-UTF-8 input exception. Attention is not
silently treated as successful input processing or as an inaccessible stuck job.

`idleModelCalls` in this old trial is **inferred from persisted per-job call
reservations and their timestamps**, not a direct continuous inference-server
request counter. It excludes uninstrumented activity. The old frozen snapshot
also lacks an independent monotonic uptime log. Its elapsed-time evidence uses
actual UTC heartbeat records, with regressions and gaps checked rather than
inventing missing time. PID existence does not independently prove executable
identity or one-writer ownership; the Windows lifecycle proof establishes that
boundary separately. Do not retrofit counters into this running trial.

## Additional real transport failure fixture

Run `node test/qa-unattended-live.mjs`. It creates only its own temporary profile,
loopback endpoint and two controlled local destinations. It uses the production
HTTP/SSE provider adapter and real TCP sockets with synthetic model frames.
There is no inference, paid request or external account.

On Windows, the 2026-11-09 19:16:03.471 UTC run verified:

- A future enabled schedule made zero directly counted HTTP requests while idle.
- Stop closed a held partial tool-argument stream in 13.75 ms; no tool dispatched.
- Stop after a verified write closed the held final stream in 10.35 ms.
- Closing/reopening the runtime and explicitly continuing the same job reused its
  durable receipt. The destination remained byte-identical and the write ran once.
- An actually refused loopback connection produced visible attention. Resume
  required review. Restoring the endpoint and reviewing created one intended output.
- An insufficient token allowance dispatched no HTTP request. An escaping path
  created no out-of-project file or output receipt.

The run recorded eight requests, eight closed responses, two intended committed
writes and zero duplicate effects. Its two stable output IDs are retained in
the private `unattended-acceptance.json`, with destination digest
`cded5a57417e2bd66859ab06ce97155a0453eb07280680a9f98c7ff33d805090`.
These short latency samples are observations, not p95 values or speedup claims.
No actual process crash, desktop lock, sleep, reboot or WAN condition is inferred
from this fixture. Earlier actual Windows crash proofs are reused separately.

## Read-only process resource sample

```powershell
powershell -NoProfile -File scripts/sample-worker-resources.ps1 -WorkerPid <isolated worker PID> -DurationSeconds 60 -IntervalSeconds 5
```

The sampler reads counters for at most 60 seconds, checks PID start-time identity
and emits JSON lines. It never captures the desktop or changes the process.
From 19:12:33 to 19:13:33 UTC on 2026-11-09, the existing trial worker had:

- Working set 125,992,960–127,057,920 bytes; private memory 84,234,240–85,291,008 bytes.
- 905 handles and 45 threads throughout.
- 0.015625 seconds additional process CPU time during the sample.

This is a signed-in, window-closed process sample. It measures no GPU memory,
whole-machine power, long-run leak rate or matched a2.4 improvement.
