# Native precision and fit controls

SAFELOAD03/04/05 extend the a2.7 native CPU route. A precision slider appears
before Start for supported complete Safetensors text packages. Its discrete
positions are Q4_0, Q5_0, mixed Q4/Q8 decoder halves, Q8_0 and original float32.
The named selector exposes the same profiles. Start and explicit Use remain
separate; successful profile choices and verified effective precision are saved
for the matching model ID and immutable adapter. Changing files, profile or
adapter invalidates that matching display until another verified load.

GGUF encodings and external connections keep their existing controls. The native
route remains CPU-only with Default context, automatic cores and an optional
thread count. Unsupported GPU/offload and RAM/GPU splitting are stated directly.
All startup options remain strict data. No engine patch, arbitrary topology file,
repository code, shell, MCP service or raw native listener was introduced.

## Actual formats and effective budget

The pinned official Mistral.rs 0.9.5 library applies each selected load profile.
For quantized loads its official UQFF verification path records actual stored
formats, tensor shapes and fallbacks. The adapter reduces that report to safe
numeric metadata, includes residual floating tensors, computes the packed byte
budget per parameter, and deletes all verification files before publishing
readiness. CPU inference then uses the already-loaded model. The public model
package stays byte-exact.

This adds startup work and temporary disk use, potentially close to another
quantized model's size. The red disk estimate includes that workspace. Stop and
failed-start cleanup own the whole private staging directory. There is no
persistent converted-model export or reuse of unverified third-party artifacts.

Original mode uses the native float32 loader and records its logical precision.
Quantized mode reports a measured **packed weight budget**, including format and
scale metadata. That value is distinct from process RAM, activation precision,
context memory and a uniform bit width for every tensor. Norms and promoted
output heads may retain higher precision. Model/profile/adapter identity and the
verification timestamp are saved with the result; stale records do not label a
new profile as verified.

The strict private pipe is protocol 3. Readiness requires the selected profile
and a valid effective-precision summary. The existing Faber endpoint remains
authenticated and loopback-only, rejects browser origins and privileged routes,
and preserves stream cancellation/reuse. The native executable and dependency
payload remain installer-owned and outside self-upgrade authority.

## Three resource tiers

The normal picker labels all three tiers with text and binary byte units:

| Tier | Display | Meaning |
| --- | --- | --- |
| Selected VRAM | Green | Zero selected on this CPU backend; GPU placement/offload is unsupported. |
| System RAM | Orange | Estimated resident weights, full default-capacity context and conservative startup workspace, plus reserved headroom. |
| SSD/HDD backing | Red | Existing original weights and additional temporary workspace, with free capacity and reserved headroom. Physical drive type is unknown. |

Safetensors headers are inspected with an 8 MiB per-file/32 MiB aggregate metadata
bound and at most 1,024 shards/100,000 tensor descriptors, validated shapes,
byte ranges, duplicate/overlap rejection, file identity checks and link guards.
No tensor data or model code is executed for this preview. Missing or unsupported
metadata reports an unknown estimate rather than zero or a successful fit.

Weight estimates use tensor shapes and supported block encodings, including
sensitive output/embedding promotion and shape-related higher-precision cases.
The mixed profile applies Q4 to the first half of decoder layers and Q8 to the
remaining layers; other tensors follow the backend's precision rules.
Context estimates use two float32 K/V arrays times decoder layers, KV heads,
head width and default context capacity. Sliding-window, lazy allocation and
model-specific caches can differ. Startup workspace reserves at least 256 MiB
or 15% of float32 weights; quantized loads additionally reserve the float32
working weight size. RAM headroom is the greater of 2 GiB or 15% of system RAM.
Disk headroom is the greater of 1 GiB or 2% of volume capacity.
Temporary disk estimates include 10% weight-format overhead, staged and generated
support-file copies, and a 16 MiB metadata/report reserve.

The disk comparison uses **additional** workspace against free capacity; it does
not charge existing source weights against free space again. Disk backing does
not become VRAM. Estimates do not reserve memory, force an allocation cap or
promise successful loading. After Start, the picker compares them with confirmed
CPU placement and a separately labeled process working-set sample at readiness.
Context can grow after that sample.

## Acceptance and 10-bit probe

November 9, 2026, Windows x64. The changed narrow adapter used the unchanged
official engine at commit `465191d0b0a7e2432d327b0de06204ab3f94d3a2`.
Its reviewed 65,950,208-byte executable has SHA-256
`b22d6ac816270cb52e3495e3a53a77dc9d7c0474c610325ac2cc0e125ae56d5a`.
The source and complete six-file payload are pinned in
[safetensors-runtime-lock.json](../build/safetensors-runtime-lock.json).
Build/privacy/license instructions remain in the [native build guide](a2.6-safetensors.md).

Actual registered lifecycle tools and completions used the original public
Apache-2.0 `HuggingFaceTB/SmolLM2-135M-Instruct` package at
`12fd25f77366fa6b3b4b768ec3050bf629380bac`, with 134,515,008 weight parameters.

| Requested profile | Actual tracked formats | Residual float32 parameters | Verified budget |
| --- | --- | ---: | ---: |
| Q4_0 | 210 Q4_0, one promoted Q5_1 | 35,136 | 4.8287 packed bits/parameter |
| Q5_0 | 210 Q5_0, one promoted Q8_0 | 35,136 | 6.1441 packed bits/parameter |
| Mixed Q4/Q8 | 105 Q4_0, 105 Q8_0, one promoted Q5_1 | 35,136 | 6.4072 packed bits/parameter |
| Q8_0 | 211 Q8_0 | 35,136 | 8.5119 packed bits/parameter |
| Original | Float32 loader execution | Included | 32 logical bits/parameter |

All four quantized cases reported zero format fallbacks. Each profile passed
real CPU completion, SSE, cancel followed by another completion, profile/effective
precision persistence, missing-key/origin rejection, absence of privileged
routes and native listeners, unchanged original hashes, Stop, process exit and
staging/key removal. Separate qualification proved inference still worked after
the temporary verification artifacts had been deleted.

The actual official parser was called with the 10-bit candidate `q10_0`; it
rejected it as unknown and listed its supported native formats. The adapter's
native unit test retains that probe. The UI explicitly marks 10-bit unavailable;
it does not round that request to an unrelated encoding or describe mixed Q4/Q8
as 10-bit. Q5_0 and the actual mixed profile above are working intermediate choices.

```powershell
$env:FABER_SAFETENSORS_MODEL_DIRECTORY = '<absolute complete public package directory>'
foreach ($mode in @('none','q4_0','q5_0','mixed_q4_q8','q8_0')) {
  $env:FABER_SAFETENSORS_QUANTIZATION = $mode
  node test/safetensors-managed-live-smoke.mjs
  if ($LASTEXITCODE) { throw 'Native precision acceptance failed' }
}
npm exec electron . -- --smoke-local-models
npm test
npm run smoke
```

The real Electron fixture exercised the slider before Start, all three resource
tiers, unsupported 10-bit state, effective precision, explicit Use, controlled
chat, Stop and agent default profile restoration. Existing GGUF lifecycle checks
remain in that fixture. Bounded metadata/fit tests, native DTO/parser tests, the
full regression suite and general bridge/renderer smoke passed. Full payload
hash/privacy/source checks remain packaging gates. No paid model request or
installed user profile was used.

These samples establish execution, formats and lifecycle; they are not a
benchmark of quality, sustained throughput or memory fit across architectures.
Native GPU/offload, a true 10-bit codec, useful native model tool-selection
quality and clean-machine installer execution remain unqualified.
