# Native Safetensors chat

SAFELOAD01 uses a small Faber worker linked to the official Mistral.rs 0.9.5
library at commit `465191d0b0a7e2432d327b0de06204ab3f94d3a2`.
It does not redistribute or launch the stock upstream server. The original
v0.9.5 CLI remains a separate historical [qualification fixture](a2.5-runner-qualification.md).
Its browser-accessible upload/delete/reload surface made that CLI unsuitable
for the managed Faber boundary, even with optional code execution disabled.

## Model selection and limits

Use a complete original text package with `config.json`, `tokenizer.json` and
all selected Safetensors shards. The host accepts upstream language-model
families `llama`, `qwen2`, `qwen3`, `qwen3_moe` and `mistral`. This is an explicit
allowlist, not a claim that every checkpoint in those families has been tested.
Custom `auto_map` code and prequantized `quantization_config` checkpoints are
rejected. Music/diffusion component pipelines cannot become chat connections.

The installed route is CPU, float32, one active sequence, Default context.
Automatic/CPU mode, automatic core placement, disk-backed memory enabled and an
optional thread count are accepted. Other placement/context settings produce
actionable errors. RAM can exceed source weight size, before context and working
buffers. This release does not claim native GPU support, load-time quantization,
vision, MTP, useful tiny-random-model output quality or a benchmark improvement.

Start keeps the chat's selection until **Use in this chat**. Stop applies to
the owned model process. Existing GGUF and external connections keep their own
runtime and configuration paths.

## Process and network boundary

The host verifies the pinned executable, imported CRT and license payload before
loading. It stages exactly the selected weight names using same-volume hardlinks
and copies checked configuration/tokenizer data. The staged index cannot name
an unselected weight. NTFS is the normal supported Windows filesystem. Temporary
entries are removed on ordinary Stop or shutdown; original weights are retained.

The worker receives one absolute staged directory argument and requires
`HF_HUB_OFFLINE=1`. Token sources are disabled. Its only command interface is
bounded, length-prefixed JSON through inherited stdin/stdout. There is no raw
worker socket, HTTP service, repository-code loader, shell, MCP or native tool
dispatcher. Model-produced function calls remain data for Faber's normal tool
registry and approval authority. The upstream inference library itself retains
its normal OS permissions; this worker is not an operating-system sandbox.

Faber owns the separate random-port `127.0.0.1` HTTP endpoint. It requires a
random private Bearer key and rejects any browser `Origin`. Only authenticated
health, model/property discovery and text completion routes are exposed. Request,
frame and response sizes are bounded; input fields are allowlisted. Cancellation
passes over the pipe and allows another request. Stop closes this endpoint,
terminates the child and removes staging and key material. No unauthenticated
listener is exposed on the LAN.

## Locked build and packaging

The worker's [Cargo.toml](../native-safetensors/Cargo.toml) and
[Cargo.lock](../native-safetensors/Cargo.lock) pin the official library and
native dependencies. Candle is pinned to
`66a8cf184a5a519671454066b1b9efd446ec9f5c`. The acceptance build used Rust
1.99.1 stable on Windows x64 with the Microsoft C++ toolchain and the library's
default features disabled. No engine patch or fork is required.

Keep the Cargo cache and target outside the checkout and synchronized storage.
After fetching the locked dependencies in an isolated build cache, build with
both Windows path spellings remapped. `--offline` deliberately fails if a pinned
dependency has not been fetched:

```powershell
$env:CARGO_HOME = '<absolute isolated cargo cache>'
$env:CARGO_TARGET_DIR = '<absolute isolated target directory>'
$env:CARGO_BUILD_JOBS = '2'
$buildHome = [Environment]::GetFolderPath('UserProfile')
$buildHomeForward = $buildHome.Replace('\', '/')
$env:CARGO_ENCODED_RUSTFLAGS = @(
  '-C', 'target-cpu=generic',
  "--remap-path-prefix=$buildHome=/faber-build-home",
  "--remap-path-prefix=$buildHomeForward=/faber-build-home"
) -join [char]31
Remove-Item Env:RUSTFLAGS -ErrorAction SilentlyContinue
$env:AWS_LC_SYS_CFLAGS = "/we4013 /experimental:deterministic /pathmap:$buildHome=/faber-build-home"
cargo build --release --locked --offline --manifest-path native-safetensors/Cargo.toml
if ($LASTEXITCODE) { throw 'Native worker build failed' }
cargo test --release --locked --offline --manifest-path native-safetensors/Cargo.toml
```

Collect notices from that same worker graph, not the full upstream CLI. Use
Cargo's `--format-version 1` metadata and
`cargo tree --locked --offline --target x86_64-pc-windows-msvc --edges normal,build --prefix none`
with this manifest. Save their UTF-8 outputs outside the checkout, then run:

```powershell
node scripts/collect-safetensors-notices.mjs '<metadata JSON>' '<worker cargo tree text>' '<notice output directory>'
```

The collector records 520 normal/build packages and 306 deduplicated notice
texts for the qualified graph. It includes vendored native C/assembly license
files and preserves packaged license/copyright notices,
exact source URLs and declared SPDX licenses. If a crate omits license files,
the inventory identifies its standard-text fallback. Review the result before
replacing the two corresponding files under `build/licenses`; the inventory is
reproducible evidence, not a legal certification. The MIT upstream license,
Microsoft redistributable notice and Rust standard-library notices are retained.

Provision only the worker, its actually imported app-local CRT and notices:

```powershell
node scripts/prepare-safetensors.mjs --build '<target directory>/release' --redist '<reviewed Microsoft x64 CRT directory>' --record
```

`--record` is an explicit maintainer review step for new immutable bytes. Normal
provisioning omits it and must match the reviewed
[runtime lock](../build/safetensors-runtime-lock.json). That lock includes
executable/dependency hashes and the normalized crate source hash. Preparation,
prepack and after-pack scan the full native binary/DLL bytes for private build
paths, including `resources/safetensors-runtime` outside `app.asar`. A source
remap alone is insufficient evidence: the first build's mixed-slash cache paths
were found by the actual executable scan and rejected before packaging.
The pinned AWS-LC C dependency also needs its official `AWS_LC_SYS_CFLAGS`
setting above: Rust flags do not remap C `__FILE__` diagnostics. MSVC's
deterministic path mapping was checked on an actual C object. The acceptance
flags also treat MSVC implicit function declarations as errors (`/we4013`), so
AWS-LC's compile-only builtin probe rejects unavailable byte-swap functions
instead of selecting them and failing at link time. Upstream source is unchanged.
The acceptance
build home has no spaces; if using a build home with spaces, check the compiler
flag parser's quoting and inspect the resulting bytes before recording them.

Only the validated runtime directory is an installer resource. Cargo caches,
target trees and PDBs are excluded. The native inference crate and compiled
payload remain outside the self-upgrade source allowlist; changing this engine
requires a reviewed application release. The independent metadata worker keeps
its existing upgrade contract.

## Acceptance evidence

November 9, 2026, Windows x64. The public package
`hf-internal-testing/tiny-random-LlamaForCausalLM` was downloaded through the
ordinary pinned Faber package path at revision
`9fb191250dd56d0ba7ec9785a025ed29c03d5998`. Its seven original files total
6,477,074 bytes, including 4,131,280 bytes of Safetensors weights. No conversion,
Python model execution, paid request or user profile was involved.

```powershell
$env:FABER_SAFETENSORS_MODEL_DIRECTORY = '<absolute complete downloaded package directory>'
node test/safetensors-managed-live-smoke.mjs
npm exec electron . -- --smoke-local-models
npm test
npm run smoke
```

The real-worker fixture uses the registered `local_models_list`,
`local_model_start` and `local_model_stop` tools with the normal Computer grant.
It checks actual CPU load, completion and streaming; cancel followed by another
completion; model alias isolation; missing-key and browser-origin rejection;
absence of upload/reload/UI/MCP routes; zero worker-owned listening sockets;
process exit, closed endpoint, removed staging/key files after Stop; and that
Start does not change the chat selection. Its report is written to an isolated
temporary directory. The tiny random model establishes loader/transport
operation, not useful generation quality or tool selection accuracy.

The Electron fixture separately exercises the actual picker Start, explicit
Use, chat completion and Stop path with a controlled private-pipe child, plus
agent tool Start/Stop. It preserves existing GGUF success/failure/load-cancel
checks. Focused tests cover the authenticated boundary, immutable staging,
index/path rejection, unsupported settings, pipe cancellation/reuse, hashes and
full binary privacy checks. The full suite and general Electron smoke passed.

Clean-machine installer execution, a useful instruction model's native tool
calling, architecture-wide coverage and native GPU/quantization/MTP remain
separate acceptance work. The earlier managed GGUF MTP positive/negative tests
remain recorded in the a2.5 qualification document.
