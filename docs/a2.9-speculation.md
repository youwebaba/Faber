# Managed MTP and separate drafts

The local picker has Off, Native MTP and Separate GGUF draft modes before Start, plus a maximum speculative-token count from 1 to 16. Successful settings persist per scanner model identity. Changes apply after Stop/Start. Unknown future settings remain intact and require an explicit supported choice. The same profile is available through the registered `local_model_start` tool; poll `local_models_list` for readiness and effective options.

Native MTP is qualified for complete `qwen35` GGUF targets containing actual `nextn` tensor quartets (`eh_proj`, `enorm`, `hnorm`, `shared_head_norm`) at one head prefix. A repository or filename containing MTP is insufficient. Missing heads, incomplete metadata, inconsistent shards and other architectures are refused. Separate drafts must be distinct complete GGUF assets with matching architecture; hardlink aliases of target weights are refused. The native runner validates vocabulary compatibility. The adapter also requires startup implementation/token-count logs and authenticated speculative slot confirmation, so a runtime that disables incompatible speculation cannot silently become ready.

Separate-draft placement is currently qualified for CPU mode only. Select and save CPU hardware first. Native MTP uses existing managed GGUF hardware controls. Safetensors remains a separate CPU/private-stdio route: the pinned native library's MTP path needs PagedAttention, which this backend does not provide. Its picker explains that only Off is supported. External Ollama/API providers keep their own settings. No engine changes, extra inference services or downloads are introduced by these controls. Standalone external MTP-head sidecars, other native architectures, GPU draft placement, and Safetensors speculation are unqualified and unavailable.

Effective status shows the verified implementation and token count, native draft vocabulary validation, and last completed-request drafted/accepted/decode counters. These are runtime measurements, not predicted speedups. Readiness working-set samples are separate from peak memory; paging, context growth and the draft add costs. The adapter uses bounded metadata, bounded authenticated slot inspection, existing owned-process/key cleanup and cancellation. Both target and draft identities are protected from deletion while loaded.

## Reproducible actual CPU acceptance

Use the existing pinned runtime and public weights in an isolated cache, never the installed user profile. Set `FABER_LLAMA_EXECUTABLE` to the pinned executable and `FABER_SPECULATION_MODEL_DIRECTORY` to the cache library root, then run:

```powershell
node test/speculation-managed-live-smoke.mjs
node test/speculation-incompatible-live-smoke.mjs
```

Runtime: unchanged llama.cpp commit `a37cc46104eb50900d5ab4a9ba02a0abdac039db`. Public model repository: `unsloth/Qwen3.5-0.8B-MTP-GGUF`, immutable revision `cf8a611f6ed2c2060046219a19f12cd3d5ecd67c`. Target `Qwen3.5-0.8B-Q8_0.gguf`, SHA-256 `c54f8b67069c70085b98440de696b44da8250250ac69a961b41133def876e262`; draft `Qwen3.5-0.8B-Q4_K_M.gguf`, SHA-256 `ac7c9d7a1b3e3695bb3bd50f8ceaa97f9c93e99ccc3d3d1a620301b6dd6d3d86`. The draft is a different lower-precision encoding of the same parameter-count checkpoint, not a smaller-parameter model. Both models retain their embedded native heads; separate-draft mode uses the explicit full draft asset.

Declared hardware: Intel Core i7-14700K, 68,422,639,616 bytes system RAM; two CPU threads, GPU layers 0/device none for target and draft, mmap, one slot, context 2,048. All modes used verbosity 4, temperature 0, seed 42, maximum draft count 3, three uncached 64-token text samples. Client first-token latency is measured on the first nonempty SSE content chunk; decoding throughput comes from the native final timing object.

| Mode | Median decode tokens/s | Median first content (ms) | Drafted / accepted per sample | Ready / after-request working set (GiB) |
| --- | ---: | ---: | --- | --- |
| Off | 30.28 | 170.89 | 0 / 0 | 1.142 / 1.252 |
| Native MTP | 37.46 | 183.07 | 51 / 45 | 1.251 / 1.402 |
| Separate Q4 draft | 22.16 | 276.30 | 48 / 46 | 1.932 / 2.187 |

These short samples establish operation and show that high acceptance alone does not imply faster inference. Native MTP improved decode throughput here while first-token latency increased; the separate draft was slower and consumed more memory. They are not sustained, GPU, or general model-quality benchmarks. All three produced byte-identical greedy text and the exact forced `fixture_add({a:17,b:25})` call, which executed through the real registered tool and returned 42. Forced tool choice does not qualify autonomous tool selection. Native completed-request acceptance counters also reached the normal model state.

The negative fixture changes ordinary vocabulary token 1306 in a private independent draft copy with unchanged architecture. The native runner emits incompatible-vocabulary rejection; Faber never becomes ready or saves a managed provider. Owned copies are removed afterward. Original target/draft SHA-256 values stay identical before and after acceptance. Every owned process is stopped, ports become unreachable and key files are removed. The real Electron fixture separately covers pre-Start mode/count/draft choice, effective status and Start/Stop alongside existing GGUF and Safetensors flows.
